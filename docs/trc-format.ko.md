# TRC 아카이브 포맷

쥬라기원시전2가 게임 데이터를 하나로 묶는 아카이브 포맷(TRC) 분석 자료다. 파일은 32바이트 엔트리가 늘어선 파일 테이블로 시작하고, 그 뒤에 각 파일의 데이터가 이어진다. 아래 내용은 더랭커의 `jw2_01.trc`(파일 14개, 전부 무압축)로 확인했다.

## 헤더 엔트리

첫 엔트리는 파일이 아니라 헤더다.

```
54 52 43 1A   "TRC" + 0x1A
0E 00 00 00   파일 개수
0E 00 00 00   파일 개수 (같은 값이 한 번 더)
E0 01 00 00   테이블 전체 길이 (헤더 엔트리 포함, 32 × 엔트리 수)
00 × 16       0
```

`0x0C` 의 테이블 길이를 32로 나누면 엔트리 개수가 나오고, 헤더 엔트리를 빼면 파일 개수다. 파일 데이터는 테이블이 끝나는 자리(이 값)부터 시작한다.

## 파일 엔트리

엔트리 하나가 파일 하나를 가리킨다. 모든 값은 리틀엔디언이다.

예시 (`fe1215rd.fn`):

```
66 65 31 32 31 35 72 64 2E 66 6E 00  파일명 "fe1215rd.fn" (null 종료)
00 B8 00 00                          데이터 시작 위치 (테이블 끝 기준)
00 B5 00 00                          원본 크기
00 B5 00 00                          압축 크기
21 4D                                체크섬
00 00                                압축 방식
00 00 00 00                          0
```

| 오프셋 | 크기 | 내용 |
|---|---|---|
| `+0x00` | 12 | 파일명, null 종료 |
| `+0x0C` | 4 | 데이터 시작 위치. 테이블 끝을 0으로 하는 상대 위치라 첫 파일은 0이다 |
| `+0x10` | 4 | 원본 크기 |
| `+0x14` | 4 | 압축 크기 |
| `+0x18` | 2 | 체크섬. 파일 데이터의 모든 바이트를 더한 값의 하위 16비트. 패킹 뒤에 데이터를 직접 고치면 이 값은 갱신되지 않는다 |
| `+0x1A` | 2 | 압축 방식. 00 무압축 · 01 사전 기반 · 02 ZIP |
| `+0x1C` | 4 | 0 |

## 압축 방식

압축 방식 필드가 파일마다 있어서, 한 TRC 안에서도 파일마다 무압축·사전 기반·ZIP이 섞일 수 있다.

## 이 추출기가 읽는 값

이 도구는 무압축 아카이브를 대상으로 한다. 헤더에서 테이블 길이로 엔트리 개수를 구하고, 엔트리마다 파일명(`+0x00`)과 크기(`+0x14`)를 읽는다. 파일 데이터는 테이블 바로 뒤부터 테이블 순서대로 이어져 있어서, 크기만큼 순서대로 잘라내 복원한다.

## 재조립 목록 (.trl)

추출과 동시에 `<원본이름>_file_list.trl` 을 만든다. 각 파일을 어떤 순서로 다시 묶을지 지시문 형태로 적어, 나중에 재패킹할 수 있게 한 목록이다.
